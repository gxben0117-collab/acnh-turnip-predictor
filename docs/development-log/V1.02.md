# 開發日誌 V1.02

日期：2026-09-10

## 問題

使用者直接用檔案總管雙擊 `index.html`（`file://` 協定開啟，不是透過網頁伺服器），頁面整個無法使用。

## 原因

`app.js` 原本用 `<script type="module" src="./app.js">` 載入。瀏覽器的 CORS 規則不允許 `file://`
底下的 module script 去載入外部 `.js` 檔案（即使是同資料夾），會直接被擋下，整包 JS 完全不會執行，
畫面卡在「尚無資料」的初始狀態。GitHub Pages 上線版本因為是 `https://` 協定，不受這個限制影響，
所以先前用 Playwright 對線上網址驗證時沒發現這個問題。

用 Playwright 開 `file://` 協定重現，console 錯誤：

```
Access to script at 'file:///.../app.js' from origin 'null' has been blocked by CORS policy:
Cross origin requests are only supported for protocol schemes: chrome, chrome-untrusted, data, http, https.
```

## 修正

- `build.mjs`：esbuild 輸出格式從 `"esm"` 改成 `"iife"`（自我執行的一般 script，不是 ES module）。
- `index.html`：`<script type="module" src="./app.js">` 改成 `<script src="./app.js">`。

IIFE 格式在 `file://`、`http://`、`https://` 都能正常執行，不需要額外的本機伺服器，也不影響 GitHub Pages
上線版本的行為。
