# 開發日誌 V1.03

日期：2026-09-10

## 需求

使用者實際用手機操作後回報：本週價格輸入格在頁面最下方，輸入完要手動往上滑很久才看得到結論
（現在該不該賣／Pattern 機率），操作不方便。

## 做法

新增「浮動狀態列」：一個固定在畫面最上方的精簡結果列（表情符號＋建議等級＋目前價格），平常不顯示；
用 `IntersectionObserver` 監看最上方的結論卡片（`#verdict-card`），一旦使用者往下捲動、結論卡片離開
可視範圍，浮動列就會滑入畫面頂端並保持顯示，不管捲到哪個輸入格都看得到最新結論，不需要手動滑回頂端。
點一下浮動列會平滑捲回結論卡片。

- `index.html`：新增 `#sticky-bar` 按鈕元素，放在 `.app` 容器外層、`<body>` 最前面。
- `style.css`：`.sticky-bar` 用 `position: fixed` + `transform`/`opacity` 過場（不是用 `[hidden]`
  切換，因為要有滑入動畫），`.visible` class 控制顯示；`body.sticky-active` 補上等同浮動列高度的
  `padding-top`，避免顯示時蓋住原本捲到的內容。
- `src/web/main.ts`：`renderStickyBar()` 更新文字內容，`setStickyBarVisible()` 控制顯示/隱藏，
  `IntersectionObserver` 綁在 `verdictCard` 上自動觸發。

## 修正的小問題

點浮動列捲回頂端時，一開始用 `scrollIntoView` 直接觸發，但捲動動畫進行到一半時
`IntersectionObserver` 偵測到結論卡片重新進入畫面、把浮動列隱藏、`body` 的 `padding-top` 補償被移除，
版面高度在動畫途中突然改變，導致捲過頭、結論卡片標題被蓋住一小截。改成點擊時**先同步呼叫
`setStickyBarVisible(false)` 收起浮動列，再開始捲動**，讓版面高度先穩定下來，捲動就不會抓錯目標位置。
